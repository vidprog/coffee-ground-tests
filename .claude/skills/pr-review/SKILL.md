# Код-рев'ю

Ти остання автоматична перевірка перед людиною. Номер PR у `$PR`.

**Важливе обмеження:** GitHub не дозволяє автору апрувити власний PR, і формальний апрув
від агента нічого не значить. Твій результат — **коментар-рев'ю + лейбл `ai:reviewed`**.
Мердж у будь-якому разі робить людина.

## Крок 1. Збери контекст

```bash
gh pr view $PR --json title,body,files,additions,deletions,headRefName
gh pr diff $PR
gh pr checks $PR
```

Знайди повʼязаний тікет (`Fixes #N`) і прочитай його — включно зі специфікацією
або описом бага. Рев'ю без розуміння вимоги — це лінтер, а не рев'ю.

## Крок 2. Перевір по пунктах

**Відповідність вимозі**
- чи робить PR саме те, що в тікеті;
- чи не робить чогось **понад** це (найчастіша проблема агентських PR);
- чи не порушено пункти «Поза межами» зі специфікації.

**Докази**
- чи є тест на кожен критерій приймання / на баг;
- чи тест справді падав би без фікса — перевір логіку тесту, а не лише його наявність;
- чи всі перевірки зелені (`gh pr checks`);
- чи скріншоти реально показують заявлене, чи це просто головна сторінка.

**Регресії** — прицільно для цього проєкту:
- структура `TESTS` не зламана (4 варіанти, ключі `r` існують, усі поля результатів);
- `shuffle` не зламано припущенням про порядок варіантів;
- горизонтального скролу на 360px не зʼявилося;
- `prefers-reduced-motion` поважається новими анімаціями;
- нема помилок у консолі.

**Конвенції** (`CLAUDE.md`)
- ванільний JS, жодних нових залежностей і збірки;
- кольори з CSS-змінних;
- українська в інтерфейсі й коментарях;
- не зачеплено `.github/`, `.claude/`, налаштування репо.

**Обсяг**
- чи мінімальна зміна; зайвий рефакторинг поряд — зауваження, а не похвала.

## Крок 3. Напиши рев'ю

```markdown
## 🤖 Код-рев'ю

**Вердикт:** ✅ можна мерджити / ⚠️ є зауваження / ❌ не можна мерджити
**Тікет:** #N — відповідає / відхиляється в тому-то
**Обсяг:** N файлів, +X/−Y

### Докази
| Що перевірено | Результат |
|---|---|
| Тести на критерії приймання | ✅ 3 з 3 |
| Уся сюїта | ✅ 12 passed |
| Скріншоти показують заявлене | ✅ |

### Зауваження
1. **`app.js:142` — блокуюче.** Опис проблеми, конкретний сценарій, коли ламається.
2. **`styles.css:88` — дрібниця.** Опис.

Нема зауважень — так і напиши, не вигадуй для вигляду.

### На що подивитися людині
Місця, де потрібне продуктове рішення, а не технічна оцінка.

<sub>🤖 Автоматичне рев'ю · не замінює людський апрув</sub>
```

Постав лейбл на PR:

```bash
gh pr edit $PR -R vidprog/coffee-ground-tests --add-label "ai:reviewed"
```

## Правила рев'ю

- Кожне зауваження — з файлом і рядком. «Можна краще» без адреси — сміття.
- Розділяй блокуюче й дрібниці. Якщо все дрібниці — вердикт ✅ із приміткою.
- Не переписуй PR сам. Твоя робота — оцінити, а не виправити.
- Не хвали заради ввічливості. Порожня похвала знецінює справжні зауваження.
- Помітив, що PR робить більше, ніж просили — це завжди зауваження.

## Заборонено

Мерджити, апрувати через `gh pr review --approve`, закривати PR, пушити в чужу гілку.

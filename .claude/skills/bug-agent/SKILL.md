# Робота з багом

Порядок незмінний: **відтворити → зафіксувати тестом → виправити → довести**.
Фікс без відтворення заборонений: ти не знаєш, що саме лагодиш.

Номер тікета в `$ISSUE`. Репозиторій `vidprog/coffee-ground-tests`.

## Крок 0. Перевір стан

Працюй лише якщо є `type:bug` + `ai:triaged`, і немає `ai:in-progress`, `needs-info`, `needs-human`.
Постав `ai:in-progress`, зніми його наприкінці за будь-якого результату.

## Крок 1. Відтвори

```bash
npm install && npx playwright install --with-deps chromium
```

Виконай кроки з тікета **буквально**, у браузері через Playwright. Не переказуй їх — виконуй.

Якщо кроків бракує або вони суперечливі — не вигадуй. Постав `needs-info`,
напиши, який саме крок не вдалося виконати й чому.

**Не відтворилося?** Постав `bug:not-reproducible`, напиши коментар із:
що саме ти зробив (список команд і дій), що побачив натомість, скріншот поточної поведінки,
і 2–3 уточнювальні питання авторові. Не закривай тікет.

**Відтворилося?** Постав `bug:reproduced`, зроби скріншот «до» і **одразу опублікуй його в тікеті**:

```bash
node scripts/evidence.mjs before-$ISSUE --test <id>          # додай --focus, якщо баг невидимий
git checkout -b ai/$ISSUE-<опис> origin/main                 # гілка потрібна вже тут
git add docs/evidence/before-$ISSUE-*.png && git commit -m "docs: доказ відтворення #$ISSUE"
git push -u origin ai/$ISSUE-<опис>
```

Коментар у тікет — **до того, як почнеш лагодити**:

```markdown
## 🔁 Баг відтворено

**Як відтворював:** що саме зробив, по кроках.
**Що побачив:** фактична поведінка.

![до](https://raw.githubusercontent.com/vidprog/coffee-ground-tests/ai/$ISSUE-<опис>/docs/evidence/before-$ISSUE-result.png)

**Далі:** фіксую тестом і виправляю / передаю людині (якщо впевненість низька).
```

Це доказ, що баг існує. Він має зʼявитися в тікеті **раніше** за будь-який фікс —
щоб автор бачив підтвердження, навіть якщо далі робота впреться в `needs-human`.

## Крок 2. Зафіксуй тестом

Напиши Playwright-тест у `tests/`, який **падає через цей баг**. Запусти, переконайся що червоний,
скопіюй текст падіння — він піде в коментар. Тест, який не падав до фікса, нічого не доводить.

## Крок 3. Оціни впевненість

Виправляй сам **тільки якщо виконані всі** умови:

- причина локалізована до конкретної функції або рядка (не «десь у app.js»);
- є падаючий тест із кроку 2;
- фікс зачіпає ≤ 2 файли й не змінює структуру `TESTS`;
- немає продуктового вибору між кількома варіантами поведінки.

**Хоч одна не виконана** → постав `needs-human`, зніми `ai:in-progress` і напиши коментар:
відтворення, падаючий тест, 2–3 гіпотези причини з посиланнями на рядки, що саме заблокувало.
Це нормальний і очікуваний результат, а не поразка.

## Крок 4. Виправ

Гілка: `ai/$ISSUE-<короткий-опис>` від свіжого `main`. Ніколи не комить у `main`.

Мінімальна зміна, що робить тест зеленим. Не рефактори поряд, не «покращуй» сусідній код,
не додавай залежностей. Дотримуйся конвенцій із `CLAUDE.md`.

## Крок 5. Доведи

```bash
npm test                                   # уся сюїта зелена, не тільки новий тест
node scripts/evidence.mjs after-$ISSUE --test <id>    # «до» вже зроблено на кроці 1
```

Якщо баг невидимий на звичайному скріншоті (фокус, aria, стан у памʼяті) — додай `--focus`
або іншу підсвітку стану, як описано в `_shared/evidence.md`. Дві однакові картинки —
не доказ; або зроби різницю видимою, або чесно скажи, що скріншот тут нерелевантний.

Обидва скріншоти (`before-*`, `after-*`) закомить у гілку разом із фіксом.

## Крок 6. Створи PR

```bash
git push -u origin ai/$ISSUE-<опис>
gh pr create --draft --title "fix: <опис> (#$ISSUE)" --body "<тіло>"
```

Тіло PR:

```markdown
Fixes #$ISSUE

## Причина
Що саме ламалося і чому, з посиланням на `файл.js:рядок`.

## Виправлення
Що змінено і чому саме так.

## Докази
Тест `tests/<назва>.spec.js` падав до фікса:
```
<текст падіння>
```
Після фікса вся сюїта зелена: N passed.

| До | Після |
|---|---|
| ![до](https://raw.githubusercontent.com/vidprog/coffee-ground-tests/ai/$ISSUE-<опис>/docs/evidence/before-$ISSUE-result.png) | ![після](https://raw.githubusercontent.com/vidprog/coffee-ground-tests/ai/$ISSUE-<опис>/docs/evidence/after-$ISSUE-result.png) |

## Ризики
Що могло зачепитися і чому вважаєш, що ні.

<sub>🤖 Автоматичний фікс · мердж робить людина</sub>
```

Коли тести зелені — зніми draft: `gh pr ready <номер>`.

## Крок 7. Закрий цикл

Другий коментар у **тікеті** — зі скріншотом «після». Разом із коментарем «до» з кроку 1
вони утворюють пару, яку автор бага бачить не відкриваючи PR:

```markdown
## ✅ Виправлено, чекає рев'ю

**Що було:** одне речення про причину.
**Що зроблено:** одне речення про фікс.

![після](https://raw.githubusercontent.com/vidprog/coffee-ground-tests/<гілка>/docs/evidence/after-$ISSUE-result.png)

Тест `tests/<назва>.spec.js` падав до фікса, тепер зелений. Уся сюїта: N passed.
PR: #<номер> — мердж робить людина.
```

Далі зніми `ai:in-progress`.
**Тікет не закривай** — він закриється сам при мерджі PR людиною.

## Заборонено

Мерджити PR, пушити в `main`, правити `.github/` і `.claude/`,
заявляти «виправлено» без зеленого прогону, видаляти чужі тести щоб стало зелено.
